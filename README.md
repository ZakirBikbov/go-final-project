# Планировщик задач

Веб-сервер для управления задачами с поддержкой периодических повторений и аутентификации.

## Описание проекта

Планировщик задач — это веб-приложение для создания, редактирования и управления задачами. Сервер предоставляет REST API для работы с задачами и веб-интерфейс для взаимодействия с пользователем.

Основные возможности:
- Создание, редактирование и удаление задач
- Поддержка периодических задач с правилами повторения (ежедневно, еженедельно, ежемесячно, ежегодно)
- Отметка задач как выполненных с автоматическим расчетом следующей даты
- Поиск задач по заголовку, комментарию или дате
- Аутентификация через JWT токены (опционально)

## Выполненные задания со звёздочкой

- ✅ **Полная поддержка правил повторения задач**: реализованы все варианты правил повторения, включая недельные (`w`) и месячные (`m`) правила
- ✅ **Аутентификация**: реализована система аутентификации через JWT токены с использованием переменной окружения `TODO_PASSWORD`
- ✅ **Docker образ**: создан Dockerfile для сборки и запуска приложения в контейнере

## Запуск локально

### Требования

- Go 1.24 или выше
- SQLite (используется встроенная библиотека)

### Установка зависимостей

```bash
go mod download
```

### Переменные окружения

Проект поддерживает следующие переменные окружения:

- `TODO_PORT` — порт для запуска сервера (по умолчанию: 7540)
- `TODO_DBFILE` — путь к файлу базы данных SQLite (по умолчанию: `scheduler.db`)
- `TODO_PASSWORD` — пароль для аутентификации (если не установлен, аутентификация отключена)

### Пример запуска

**Linux/Mac:**
```bash
# Запуск без пароля
go run .

# Запуск с паролем
TODO_PASSWORD=12345 go run .

# Запуск с указанием порта и файла БД
TODO_PORT=8080 TODO_DBFILE=/path/to/db.db go run .
```

**Windows (PowerShell):**
```powershell
# Запуск без пароля
go run .

# Запуск с паролем
$env:TODO_PASSWORD="12345"; go run .

# Запуск с указанием порта и файла БД
$env:TODO_PORT="8080"; $env:TODO_DBFILE="C:\path\to\db.db"; go run .
```

**Windows (CMD):**
```cmd
REM Запуск без пароля
go run .

REM Запуск с паролем
set TODO_PASSWORD=12345
go run .

REM Запуск с указанием порта и файла БД
set TODO_PORT=8080
set TODO_DBFILE=C:\path\to\db.db
go run .
```

### Сборка исполняемого файла

```bash
go build -o scheduler.exe .
```

### Доступ к приложению

После запуска сервера откройте в браузере:
- Главная страница: `http://localhost:7540/`

Если установлена переменная `TODO_PASSWORD`, при попытке доступа к защищенным эндпоинтам будет запрошена аутентификация.

## Запуск тестов

### Запуск всех тестов

```bash
go test ./tests
```

### Запуск конкретных тестов

```bash
# Тест расчета следующей даты
go test -run ^TestNextDate$ ./tests

# Тест добавления задач
go test -run ^TestAddTask$ ./tests

# Тест отметки задач как выполненных
go test -run ^TestDone$ ./tests

# Тест удаления задач
go test -run ^TestDelTask$ ./tests
```

### Настройки тестов (tests/settings.go)

В файле `tests/settings.go` можно настроить следующие параметры:

- `Port` — порт тестового сервера (по умолчанию: 7540)
- `DBFile` — путь к файлу базы данных для тестов (по умолчанию: `../scheduler.db`)
- `FullNextDate` — включить тесты для всех правил повторения, включая недельные и месячные (по умолчанию: `true`)
- `Search` — включить тесты поиска (по умолчанию: `true`)
- `Token` — JWT токен для тестов с аутентификацией (по умолчанию: пустая строка)

**Важно**: Перед запуском тестов убедитесь, что сервер запущен на указанном порту. Для этого можно использовать команду:

```bash
go build -o test_server.exe . && ./test_server.exe
```

Или запустить в отдельном терминале:

```bash
go run .
```

### Тестирование с аутентификацией

Для тестирования с включенной аутентификацией:

1. Установите переменную окружения `TODO_PASSWORD`:
   ```bash
   export TODO_PASSWORD=12345
   ```

2. Запустите сервер

3. Получите токен через API:
   ```bash
   curl -X POST http://localhost:7540/api/signin \
     -H "Content-Type: application/json" \
     -d '{"password":"12345"}'
   ```

4. Скопируйте полученный токен и установите его в `tests/settings.go`:
   ```go
   var Token = `ваш_токен_здесь`
   ```

5. Запустите тесты

## API эндпоинты

### Публичные эндпоинты

- `GET /api/nextdate?now=<дата>&date=<дата>&repeat=<правило>` — расчет следующей даты выполнения
- `POST /api/signin` — аутентификация (возвращает JWT токен)

### Защищенные эндпоинты (требуют аутентификации, если установлен `TODO_PASSWORD`)

- `GET /api/task?id=<id>` — получение задачи по ID
- `POST /api/task` — создание новой задачи
- `PUT /api/task` — обновление задачи
- `DELETE /api/task?id=<id>` — удаление задачи
- `POST /api/task/done?id=<id>` — отметка задачи как выполненной
- `GET /api/tasks?search=<поиск>&limit=<лимит>` — получение списка задач

## Правила повторения задач

- `d <число>` — каждые N дней (например, `d 3` — каждые 3 дня)
- `y` — ежегодно
- `w <дни>` — в указанные дни недели (1-понедельник, 7-воскресенье), например `w 1,3,5`
- `m <дни> [месяцы]` — в указанные дни месяца, например `m 1,15` или `m -1` (последний день месяца)

## Docker

### Сборка образа

```bash
docker build -t scheduler:latest .
```

### Запуск контейнера

Базовый запуск (без переменных окружения):
```bash
docker run -d -p 7540:7540 --name scheduler scheduler:latest
```

Запуск с переменными окружения:
```bash
docker run -d -p 7540:7540 \
  -e TODO_PASSWORD=12345 \
  --name scheduler \
  scheduler:latest
```

**Запуск с подключением к базе данных на хосте и указанием всех переменных:**

**PowerShell (Windows):**
```powershell
docker run -d -p 7540:7540 `
  -v "${PWD}:/data" `
  -e TODO_PORT=7540 `
  -e TODO_PASSWORD=12345 `
  -e TODO_DBFILE=/data/scheduler.db `
  --name scheduler `
  scheduler:latest
```

**CMD (Windows):**
```cmd
docker run -d -p 7540:7540 ^
  -v "%CD%:/data" ^
  -e TODO_PORT=7540 ^
  -e TODO_PASSWORD=12345 ^
  -e TODO_DBFILE=/data/scheduler.db ^
  --name scheduler ^
  scheduler:latest
```

**Git Bash (Windows):**
```bash
# Вариант 1: с MSYS_NO_PATHCONV (рекомендуется)
MSYS_NO_PATHCONV=1 docker run -d -p 7540:7540 \
  -v "$(cygpath -w $(pwd)):/data" \
  -e TODO_PORT=7540 \
  -e TODO_PASSWORD=12345 \
  -e TODO_DBFILE=/data/scheduler.db \
  --name scheduler \
  scheduler:latest

# Вариант 2: с двойным слешем
docker run -d -p 7540:7540 \
  -v "$(cygpath -w $(pwd)):/data" \
  -e TODO_PORT=7540 \
  -e TODO_PASSWORD=12345 \
  -e TODO_DBFILE=//data/scheduler.db \
  --name scheduler \
  scheduler:latest
```

**Linux/Mac:**
```bash
docker run -d -p 7540:7540 \
  -v "$(pwd):/data" \
  -e TODO_PORT=7540 \
  -e TODO_PASSWORD=12345 \
  -e TODO_DBFILE=/data/scheduler.db \
  --name scheduler \
  scheduler:latest
```

**Примечание:** 
- При монтировании `-v "$(pwd):/data"` директория проекта на хосте монтируется в `/data` внутри контейнера
- Файл `scheduler.db` из директории проекта будет доступен контейнеру как `/data/scheduler.db`
- Для Git Bash на Windows необходимо использовать `MSYS_NO_PATHCONV=1` или двойной слеш `//data` для корректной передачи путей
